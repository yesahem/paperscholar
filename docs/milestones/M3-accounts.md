# M3 — Accounts and roles

**Status:** done locally, on branch `feat/m3-accounts` (stacked on M2). Everything that needs
a deployment or real third-party credentials is pending: the preview checks, Google
sign-in end to end, and confirming the client address across the hosted proxy (see
[Not done](#not-done)).
**Spec:** [`docs/specs/12-milestones.md`](../specs/12-milestones.md) §M3.

## Summary

People can now create an account, confirm their email, sign in and out, reset a forgotten
password and delete their account. Sign-up and sign-in work from a modal over any page or
from their own pages. An instance with no email service and no Google credentials still
works: sign-up skips verification, and an admin resets passwords from the command line.
Roles exist (`user`, `maintainer`, `admin`), `ADMIN_EMAILS` makes the first admin, and
everything under `/v1/admin` is already hidden from anyone below maintainer. Auth requests
are rate-limited per client address in Postgres.

## What was built

### API (`apps/backend`)

| Endpoint             | What                                                                                                     |
| -------------------- | -------------------------------------------------------------------------------------------------------- |
| `/api/auth/*`        | Better Auth: email + password sign-up and sign-in, sign-out, verification, reset, Google when configured |
| `GET /api/v1/me`     | The signed-in account: id, username, email, verified, avatar (null until M5), bio, role, created         |
| `PATCH /api/v1/me`   | Username (rules of spec 06 §3, at most once per 30 days) and bio; unknown fields such as `role` refused  |
| `DELETE /api/v1/me`  | With `{ confirm: "<username>" }`: deletes the account and every row referencing it, clears the cookies   |
| `GET /api/v1/config` | Now reports `signups`, `emailVerification`, `passwordReset` (new) and `googleSignIn` from configuration  |

- **Better Auth** 1.7.22 (`src/auth/auth.ts`) on Postgres through the Drizzle adapter:
  30-day sessions refreshed at most daily, a 5-minute cookie cache, `HttpOnly`,
  `SameSite=Lax`, host-only cookies (`Secure` on https), the username plugin, `role` as a
  field the client cannot set, account linking only onto a verified address, Google's
  tokens encrypted at rest, telemetry off. Routes this product replaces are disabled.
- **Middleware** (`src/middleware/`): `session()` on every `/v1` route; `requireAuth`,
  `requireVerified`, `requireRole` (reads the stored role, answers 404) and
  `requireFeature`; `originCheck()` in front of `/v1` and `/api/auth`.
- **Rate limiting** (`src/services/rate-limiter.ts`): fixed-window counters in
  `rate_limit_counters`, one upsert per request, plugged into Better Auth's
  `customStorage`. Sign-in, sign-up, reset and resend: 10 per 10 minutes per address.
  Better Auth's 429s gain `Retry-After`; its responses gain `X-Request-Id`.
- **Email** (`src/adapters/email/`): `log` (default in development; refused in production),
  `resend` (HTTP API, no SDK) and `smtp` (nodemailer). Two text-first templates: verify
  and reset. Delivery errors never carry the address, body or credentials.
- **`ADMIN_EMAILS`**: admin at sign-up, or on confirming the address when the instance
  verifies emails.
- **Commands:** `bun run admin:grant <email> <role>` (refuses to demote the last admin),
  `bun run admin:password <email>` (reads the password from stdin, signs out everywhere),
  `bun run auth:schema` (regenerates the Better Auth tables).
- **New variables**, each in `apps/backend/.env.example`: `BETTER_AUTH_SECRET` (required),
  `DATABASE_URL` (now required), `ADMIN_EMAILS`, `ALLOW_SIGNUPS`,
  `REQUIRE_EMAIL_VERIFICATION`, `AUTH_RATE_LIMIT_MAX`, `AUTH_RATE_LIMIT_WINDOW_SECONDS`,
  `CLIENT_IP_HEADER`, `TRUSTED_PROXIES`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`,
  `EMAIL_DRIVER`, `EMAIL_FROM`, `RESEND_API_KEY`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`,
  `SMTP_USER`, `SMTP_PASSWORD`.

### Database (`packages/db`)

- `user`, `session`, `account`, `verification`, generated by Better Auth's CLI
  (`auth@1.7.22`) and converted to `timestamptz` by a scripted second step;
  `user_role_check`; `profiles` (bio, avatar key, `username_changed_at`); the foreign key
  from `content_candidates.created_by` to `user`, `on delete set null`.
- Migrations `0002_accounts` and `0003_user_role_check`.
- `@repo/db/testing`: `createTestDatabase()` gives each test file its own migrated
  database.
- Drizzle's query operators are re-exported, so every package uses one Drizzle copy.

### Shared contract (`packages/shared`)

- `meSchema`, `updateMeSchema`, `deleteMeSchema`, `usernameSchema`, `roleSchema`.
- `@repo/shared/accounts`: roles, `hasRole`, username rules and the reserved list, password
  and bio limits, with no zod, for browser code.
- `@repo/shared/errors`: the error codes and messages without zod.
- `envBooleanSchema`, `envListSchema` for `true`/`false` and comma-separated variables.

### UI primitives (`packages/ui`)

- `DropdownMenu`, `DropdownMenuItem`, `DropdownMenuLabel`, `DropdownMenuSeparator`: the
  WAI-ARIA menu button (arrow keys, Home, End, Escape returns focus, Tab and outside
  clicks close).
- **Fixed in `Dialog`:** the browser fires `close` as a separate task, so a dialog closed
  and quickly reopened was closed again by the late event. Found by the browser checks;
  the decision is now `dialogCloseAction()`, with tests.

### Web (`apps/web`)

| Route             | What                                                                                         |
| ----------------- | -------------------------------------------------------------------------------------------- |
| Header            | "Sign in" opens the modal; signed in, a menu with the username, email and "Sign out"         |
| Sign-in modal     | Sign in or create an account over the current page; Google when the instance offers it       |
| `/login`          | Sign-in page; returns to `?next=` when it is a path on this site                             |
| `/signup`         | Sign-up page; explains when sign-up is off                                                   |
| `/reset-password` | Ask for a link; with a token, choose a new password; explains when the instance has no email |
| `/verify-email`   | Where verification links land: confirmed, or why the link failed                             |
| Banner            | Under the header for an unconfirmed address, with "Resend email"                             |

- `lib/auth/auth-api.ts` calls Better Auth's routes directly with validated responses;
  `lib/queries.ts` has `useMe()` and `useInstanceConfig()` (TanStack Query 5.104.0).
  `useMe()` asks `/api/auth/get-session` first, so visitors' pages have no failed request.
- Messages for every Better Auth refusal point at the field to fix (`lib/auth/messages.ts`).
- The privacy page now lists what an account stores.

### API contract (`postman/`)

New `Accounts` folder: signed-out `401`, sign-up with cookie flags checked, `GET` and
`PATCH /v1/me`, a `role` field and a cross-site write refused, `/v1/admin` as a user
(`404`), a wrong deletion confirmation, deletion, and `401` afterwards. Better Auth routes
are excluded from the envelope check. 20 requests, 76 assertions. CI generates a
`BETTER_AUTH_SECRET` per run.

## How to run

```sh
docker compose -f docker-compose.dev.yml up -d
echo "BETTER_AUTH_SECRET=$(openssl rand -base64 32)" >> apps/backend/.env   # once
bun run db:migrate
bun dev
```

Open <http://localhost:3000> and choose **Sign in**. Emails print in the `bun dev` output;
follow the link to confirm. Other commands:

```sh
bun run admin:grant you@example.com admin
echo 'a new password' | bun run admin:password you@example.com
bun run api:contract
```

To try a minimal instance, start the backend with `EMAIL_DRIVER=none`.

## Deviations from the specs

All are reflected in the specs in this change.

1. **No Better Auth React client (06 §8).** A thin client with validated responses
   instead, to keep zod rules (AGENTS.md §1) and page weight. `useMe()` checks
   `get-session` first.
2. **Better Auth's tables use `timestamptz` (04 §3).** The generator's `timestamp` columns
   read back shifted on any host outside UTC (a test proves it). `auth:schema` converts
   them; nothing in the generated file is edited by hand.
3. **Rate limiting through `customStorage` (06 §2, 11 §3).** One fixed-window limiter on
   `rate_limit_counters` instead of Better Auth's own `rateLimit` table.
4. **`passwordReset` feature (05 §8, 13 §4).** An instance can send email without
   requiring verification, so the web app needs to know about reset separately.
5. **Verification lands on `/verify-email` (06 §4)**, which confirms and links on, instead
   of redirecting straight to `/papers`. Links last 24 hours.
6. **`profiles.username_changed_at` (04 §4)** enforces one username change per 30 days.
   `profiles` is created now; `user_stats` waits for M5.
7. **`originCheck()` also guards `/api/auth/*` (06 §6)**, because Better Auth checks
   `Origin` only when a cookie is present.
8. **`admin:password` (06 §1)** names the command-line reset the spec described.

## Things to know

- **The client address needs a trusted proxy.** Measured: `next start`'s `/api` rewrite
  adds no `X-Forwarded-For` and passes a client-supplied one through, and Next.js 16 has no
  `request.ip`. On a self-hosted box, a reverse proxy in front of `web` must overwrite the
  header, or clients can choose their own address, and in production with no header every
  visitor shares one bucket per auth route. M4's `docker-compose.yml` must include that
  proxy. On Vercel the edge sets the header; whether it survives the rewrite is untested.
- **Revocation takes up to five minutes** for a browser holding the cookie cache: sign-out
  elsewhere, password reset and deleted sessions. `GET /v1/me` and `requireRole` read the
  database, so deleted accounts and demotions apply at once.
- **JavaScript per content page is now 220–224 KB gzipped** (summing the page's script
  chunks), above M2's 187–208 KB and the 150 KB target. The header's account controls
  need TanStack Query on every page. Loading the modal's forms lazily saved nothing
  measurable, so they load with the page.
- **Rate-limit counters are never deleted yet.** Retention (one day, spec 04 §8) is the
  cleanup job in M4.
- `auth@1.7.22` (Better Auth's CLI) is a dev dependency of the backend and brings about
  120 packages; it is used only by `auth:schema`.
- The browser checks (24 for the main flows, 6 for a minimal instance) and the timing
  script ran from outside the repository with `puppeteer-core` and the local Chrome,
  as in M2. Playwright in the repository is proposed for M4.
- `bun run admin:password` reads one line from standard input; typed at a terminal, the
  password is echoed.
